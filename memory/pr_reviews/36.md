## Findings

### F1: A stale-stat changed file breaks the no-fetch probe  (fixed)

- **severity:** Warning
- **status:** fixed
- **location:** starter/bin/_checks.py:375
- **concern:** `base_blobs` listed changes with porcelain `git diff --raw`, which reads the base blob of any changed file whose index stat information is stale, so with `GIT_NO_LAZY_FETCH` both `bin/check --fetch-base` and the check died with an opaque exit 128 instead of fetching or naming the fix.
- **resolution:** The probe uses plumbing `git diff-index`, which reads no blob for stat-only changes; the partial-clone test now rewrites a changed file before the check and fetch.
- **fixed_at:** 2026-11-09

### F2: The probe's Git failures hide Git's message  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** starter/bin/_checks.py:369
- **concern:** `base_blobs` captures Git's stderr and raises `CalledProcessError`, so an unexpected Git failure there reports only the command and exit status.
- **resolution:** After F1, no known input fails these three commands, and `tracked_files` already uses the same pattern; the diagnostic gain doesn't justify another error path late in the release.

### F3: The partial-clone test never tracks `.env`  (fixed)

- **severity:** Warning
- **status:** fixed
- **location:** tests/test_partial_clone.py:117
- **concern:** The starter's `.gitignore` lists `.env`, so the fixture's `git add .` never committed it, and the test's `.env` assertions passed whether or not the check left sparse-excluded paths out or fetched them.
- **resolution:** The fixture force-adds its files, as trading commits `.env`. `assert_missing` now resolves each path first, so a path missing from the history fails the test.
- **fixed_at:** 2026-11-09

### F4: A step that writes an excluded path clears its skip-worktree bit  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** starter/bin/_checks.py:372
- **concern:** Git clears the skip-worktree bit of an excluded path that exists in the working tree. If a CI step writes `.env` before the check, `--fetch-base` fetches `.env`'s base blob and the check reports the written file.
- **resolution:** Deferred, not fixed. No adopter writes a sparse-excluded path before `bin/check`, and the robust signal, a missing index blob, also needs the no-base diff covered.
- **follow_up_issue:** https://github.com/jubishop/project-starter/issues/37

### F5: A treeless (`filter: tree:0`) checkout fails the probe opaquely  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** starter/bin/_checks.py:373
- **concern:** With `tree:0`, the base's trees are missing too, so `diff-index` exits 128 under `GIT_NO_LAZY_FETCH`. `bin/check` and `--fetch-base` then fail with only the command and its exit status, though the policy describes any `filter`.
- **resolution:** It fails closed, with no false pass and no fetch. No adopter uses a `filter`, and a treeless clone doesn't suit a job that checks out and tests code, so neither tree fetching nor narrower docs are worth a change late in the release.
